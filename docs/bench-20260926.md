# wall91 驗證與效能紀錄 2026-09-26

環境：Mac mini M4、macOS 27、兩台 1920×1080（主螢幕 MSI MP242C 在右，副螢幕 40PFH4082 在左，frame x=-1920），
設定為 `kang` preset（attention 模式、particleCount 420、30 fps）。

## 效能：wall91 自身 CPU（單核百分比）

兩種量法，**只能同一欄內互相比較**：

- **bench**：`./bench_cpu.sh`，暫停常駐、從終端機跑同一支執行檔 30 秒，取 app 自己 getrusage 的每秒平均（前 5 秒暖機不計）
- **常駐**：launchd 常駐（ProcessType=Interactive）實際在跑時，用 `ps` 的累計 CPU 時間差量 30 秒。
  會受當下系統負載影響，數字比 bench 高且較吵

| 階段 | bench 單螢幕 | bench 兩螢幕 | 常駐兩螢幕 | 記憶體（兩螢幕） |
|---|---|---|---|---|
| 基準（C，多螢幕各自一份模擬） | 2.24% | 3.51% | 6.43% | 107.8 MB |
| A 之後（單一世界、step 一次） | 2.18% | 3.28% | 5.20% | 107.8 MB |
| B 之後（非焦點螢幕 15 fps） | 2.22% | 3.07% | 4.80% | 107.7 MB |
| D 之後（kang preset，加入效果程式碼） | 見下方 D 節 | | | |

解讀：

- 單螢幕的成本幾乎不動（2.2%），符合 Phase 0 的結論：成本在 MTKView 每幀喚醒，不在模擬與繪製。
- 第二台螢幕的邊際成本：基準 +1.27% → A +1.10% → B +0.85%（bench）。A 省下的是第二份模擬；B 省下的是非焦點螢幕一半的喚醒。
- 兩螢幕比單螢幕貴的主因仍是「多一個 MTKView 在喚醒」，這部分只能靠降 fps 或遮擋暫停省。
- WindowServer 的合成成本 ps 量不準，要用 `sudo ./bench_powermetrics.sh`（見文末）。

## C：情境驗證

### (1) Spaces 切換會不會閃黑／閃舊桌布

- 這台每台螢幕只有一個桌面 Space（`com.apple.spaces` 唯讀檢查），Ctrl+→ 沒有別的桌面可切，所以用「全螢幕 App 建立新 Space 再退出」代替 Space 切換。
- 自製測試程式 `fstest` 在副螢幕開視窗→切全螢幕→4 秒後退出，同時 `screencapture -v -D 2` 錄影 9 秒（60 fps，296 幀），抽 30 fps 逐格算亮度與幀差：
  進出全螢幕的過場都是 Safari ↔ 全螢幕視窗的交叉淡化，**沒有任何全黑幀、沒有出現舊桌布**。
- 限制：副螢幕當時被 Safari 蓋滿，錄影看不到桌布本身在過場中的樣子。手動驗證步驟見文末。

### (2) Stage Manager

- `defaults read com.apple.WindowManager GloballyEnabled` = `0`（目前關閉）。依指示不改系統設定，未實測，手動步驟見文末。
- 理論上：Stage Manager 只改變一般視窗的排列，wall91 在桌布層（`desktopWindow` level、`canJoinAllSpaces`＋`stationary`），不受影響；左側縮圖區露出桌布時 wall91 會判定為可見而繼續畫。

### (3) 某螢幕有全螢幕 App

log 證據（舊架構與新架構都測過）：

### (4) 休眠／鎖定／螢幕保護程式

原本沒有處理（只靠遮擋判定，螢幕休眠時系統不一定送 occlusion）。現在監聽：
`screensDidSleep/Wake`、`willSleep/didWake`、`sessionDidResignActive/BecomeActive`、
分散式通知 `com.apple.screenIsLocked/Unlocked`、`com.apple.screensaver.didstart/didstop`。
任一成立就全部停畫＋`releaseDrawables()`，恢復時重設時鐘（粒子從停下的位置接續，不會依停了多久一次補算而瞬移）。

實測（螢保用真的分散式通知觸發；鎖定用 debug-suspend 信號走同一條路徑）：

```
[21:33:20] SUSPENDED(screensaver)  cpu=2.20%  frames=+11   ← 觸發當秒還有前半秒的幀
[21:33:21] SUSPENDED(screensaver)  cpu=0.18%  frames=+0 OK  mem=60.1MB
[21:33:22] SUSPENDED(screensaver)  cpu=0.15%  frames=+0 OK  mem=55.6MB   ← drawable 釋放，108→56 MB
[21:33:24] >>> RESUME screensaver
[21:33:25] visible   screens=2/2  fps=29.9  cpu=5.46%
[21:33:26] >>> SUSPEND locked
[21:33:27] SUSPENDED(locked)  cpu=0.21%  frames=+0 OK
[21:33:30] >>> RESUME locked
```

## B：焦點螢幕降 fps

每秒判斷一次：滑鼠所在的螢幕＋前景 App 最上層視窗所在的螢幕＝焦點，其他螢幕用 `motion.secondaryFps`（預設 fps/2）。

```
[21:47:50] >>> 焦點螢幕 1:焦點30 2:降速15
[21:47:52] visible   screens=2/2  fps=30.0 [30/15]  steps=30
[21:48:03] >>> 焦點螢幕 1:焦點30 2:焦點30      ← 測試視窗在副螢幕取得焦點
[21:48:10] >>> 焦點螢幕 1:焦點30 2:降速15      ← 測試視窗關閉
```

模擬跟著畫得最快的那台走（steps=30），降速那台只是少畫幾幀，看到的是同一片星空。

## 需要你手動做的驗證

**Spaces（桌布要露出來才看得到）**
1. 系統設定 → 桌面與 Dock → 最下面「指揮中心」，按 `+` 新增一個桌面（或四指上滑進指揮中心，右上角按 `+`）
2. 把兩台螢幕的視窗都縮小，讓桌布露出來
3. 按 Ctrl+→、Ctrl+← 來回切換幾次，注意過場中桌布是否閃黑或閃回舊桌布
4. 看 log：`tail -f ~/Library/Logs/wall91.log`，切換時不應該出現長時間 OCCLUDED
5. 測完可以把多出來的桌面刪掉

**Stage Manager**
1. 控制中心 →「幕前調度」打開
2. 確認桌布（wall91）在左側縮圖區後方照常在動；把所有視窗收進縮圖列，桌布應正常顯示
3. 開一個視窗放大蓋滿，log 應出現該螢幕 OCCLUDED
4. 關回幕前調度（恢復原本設定）

**鎖定／螢幕休眠（真的觸發一次）**
1. `tail -f ~/Library/Logs/wall91.log` 開著
2. 按 Ctrl+Cmd+Q 鎖定，等 5 秒再登入 → log 應有 `SUSPEND locked`、`SUSPENDED(locked) ... frames=+0 OK`、`RESUME locked`
3. 蘋果選單 → 睡眠（或 `pmset displaysleepnow`），喚醒後 log 應有 `screenSleep` 的 SUSPEND／RESUME，且粒子從原位置繼續、沒有跳動

**耗電總帳（需要 sudo）**
1. 關掉影片、音樂、正在跑的 build／AI 任務，顯示桌面讓兩台桌布都露出來
2. `cd ~/github-repos/wall91 && ./bench_powermetrics.sh`，輸入一次登入密碼
3. 約 3 分鐘，期間不要動滑鼠鍵盤；結束會印出「停掉／兩螢幕／單螢幕」的功耗與 WindowServer ms/s 對照
