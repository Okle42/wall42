## 1. 重開機後常駐在跑但完全不畫

**現象**：2026-09-30 重開機後桌布不動。`launchctl` 顯示 running、沒有退出紀錄；log 從啟動第一秒起就一直是
`visible screens=2/2 fps=0.0 [0/0] steps=0`，連模擬都沒推進（`steps=0`＝`draw(in:)` 根本沒被呼叫）。
沒有 SUSPENDED、沒有 OCCLUDED，MTKView 也沒 pause。

**根因**：LaunchAgent `RunAtLoad` 在登入極早期就啟動 wall42，MTKView 內部的 display link 建在
尚未就緒的螢幕上，之後永遠不觸發。旁證：重開機後主螢幕 displayID 由 `1` 變成 `3`。
`launchctl kickstart -k` 手動重啟後立即 30fps，確認與程式狀態無關、是啟動時機問題。

**修法**：`report()` 內加看門狗。條件＝沒有手動暫停、至少一個畫面沒 pause、不在剛切換的 1.1 秒內、
該秒 0 幀；連續 5 秒就呼叫 `rebuildSurfaces`（等同螢幕配置改變時的重建）。最多連試 3 次，
一旦有畫出來就歸零，避免真的壞掉時無限重建。

**驗證**：`WALL42_SIMULATE_STALL=1 WALL42_DURATION=14 ./wall42` —— 第一批畫面不接 renderer，
log 顯示 0 幀 4 秒 → `⚠ 該畫卻連續 5 秒 0 幀…重建畫面（第 1 次）` → 下一秒回到 29–30fps。
真實開機情境要等下次重開機，看 log 是否出現該行並恢復。

## 2. log 每秒一行、無上限

**現象**：`~/Library/Logs/wall42.log` 每秒一行統計，4 天 26.7 萬行、28MB，會一直長大。

**限制**：`bench.sh`／`bench_cpu.sh` 靠每秒那行解析 fps／cpu，不能直接拿掉。兩者都會設 `WALL42_DURATION`。

**修法**：
- `WALL42_DURATION>0` 或 `WALL42_VERBOSE=1` → 維持每秒一行；常駐 → 60 秒一行。
- 事件（焦點、遮擋、重建…）照常當下寫；異常（SUSPENDED/OCCLUDED 仍在繪製、0 幀）不受節流。
- stdout 是一般檔案且超過 20MB → `ftruncate` 清空（啟動時與每 10 分鐘檢查；launchd 用 append 開檔，外部輪替做不到）。

**驗證**：預先塞 22MB 假 log，以 `>>` 接 wall42 輸出 → 啟動即清空，啟動訊息完整保留，10 秒內只有 1 行統計。
