# wall42 Windows：安裝／打包結果

分支 `w2-install`（基於 `windows-w1`）。環境同 W1（Windows 11 25H2、i5-8250U、UHD 620、單螢幕 2256×1504＠150%、.NET SDK 8.0.425）。

## 做了什麼

| 項目 | 內容 |
|---|---|
| `Wall42.Win\Package.cs` | 參數分派（`--install`／`--uninstall`／`--version`／`--run`）、安裝、更新、解除安裝、HKCU Run、HKCU Uninstall、雙擊首次執行 |
| `Wall42.Win\Dialog.cs` | 不用 WinForms 的 `TaskDialogIndirect`（主程式維持純 Win32；`app.manifest` 加 comctl32 v6） |
| `pack.ps1` | `dist\wall42.exe`（self-contained 單檔）、`dist\wall42-small.exe`（framework-dependent 單檔）、`SHA256SUMS.txt`；`-Compressed` 只做量測用 |
| `tools\make_icon.ps1` → `Wall42.Win\wall42.ico` | 深色圓角方塊、中央深藍打光、藍白粒子（白色亮核）與細連線；16–256 px，小尺寸只畫主幹 4 顆 |
| 版本資訊 | Product／AssemblyTitle／Company＝wall42、Description、Version（pack.ps1 `-Version` 可覆寫）、圖示 |
| `tests\w2_install_e2e.ps1` | 沙盒 e2e，兩個 exe 各一輪 |
| 其他（各一兩行） | `Program.cs` 第一行呼叫 `Package.Dispatch`；`Config.Dir` 認 `WALL42_DATA`；`Presets.Dir` 與 `Log` 認 `WALL42_HOME` |

## 行為（對照 Mac install.sh／uninstall.sh）

- **雙擊下載的 exe**（exe 內含 presets＝packed，且不是從安裝目錄執行）：只跳 TaskDialog（繁中）說明會做什麼——
  放到 `%LOCALAPPDATA%\wall42\bin`（不需系統管理員）、presets 放到 `%LOCALAPPDATA%\wall42\presets`、
  `%APPDATA%\wall42\config.json` 不存在才建立、開機啟動並列在「設定 > 應用程式」、**不會更改系統桌布**。按「安裝」才動手；
  已裝舊版就問「更新」；同版本只說「已經安裝好了」（沒在跑就啟動）。
- **安裝／更新**：依 exe 路徑找出從 bin 跑的 wall42（別處的 dev build 不管）→ 先送 WM_CLOSE 給它的隱藏主視窗（乾淨結束）、5 秒不走才 kill
  → 原子複製（`.new` 再 rename）→ packed 安裝的 bin 只留一個 `wall42.exe` → presets（我們出的檔每次覆寫、使用者自己加的保留）
  → 設定檔只在不存在時建立 → Run＝`"…\bin\wall42.exe"` → Uninstall 機碼（DisplayName／Version／Icon／InstallLocation／
  UninstallString／QuietUninstallString／EstimatedSize／NoModify／NoRepair）→ ShellExecute 啟動（不繼承 stdout；cwd＝`%LOCALAPPDATA%\wall42`，不鎖 bin）。
- **開機啟動**的 Run 不帶參數：從 bin 執行的 packed exe 不問安裝，直接跑。
- **解除安裝**：停掉 → 拿掉 Run 與 Uninstall 機碼 → 刪 log → 刪 bin。從安裝目錄執行時（「設定 > 應用程式」就是這樣）exe 刪不掉自己：
  隱藏 cmd 在結束後重試刪除約 15 秒；啟動 cmd 前先把自己的 std handle 設成不可繼承（否則讀我們 stdout 的呼叫者要等 cmd 結束）。
  **保留**：`%APPDATA%\wall42`（設定檔、信號）、`%LOCALAPPDATA%\wall42\presets`（跟 Mac 一樣；日後桌布同步的備份也會放在保留區）。
- 沒有 console（「設定 > 應用程式」呼叫）且沒 `--quiet` 時結果顯示在對話框；從終端機呼叫則 AttachConsole 印出來。
- 路徑比對一律 `GetLongPathName` 展開（`%TEMP%` 常是 8.3 短路徑，ShoWork42 W4 的坑）；行程路徑用 `QueryFullProcessImageName`。

## 大小與記憶體

| 檔案 | 大小 | 需要 |
|---|---|---|
| `wall42.exe` | 65.2 MB | 什麼都不用裝（沒有 WinForms／WPF，所以只帶 Microsoft.NETCore.App，比 ShoWork42 的 155 MB 小） |
| `wall42-small.exe` | 2.5 MB | .NET 8 Runtime（不是 Desktop Runtime） |
| （不採用）壓縮單檔 | 33.8 MB | — |

記憶體（停畫中＝桌面被視窗蓋住，使用者平常的狀態；同一個預設設定；**exe 用沒跑過的新檔名**，理由見下）：

| 版本 | 工作集 | Private |
|---|---|---|
| wall42.exe（self-contained，不壓縮） | 52.2 MB | 16.4 MB |
| wall42-small.exe | 50.8 MB | 15.3 MB |
| 壓縮單檔 | 74.9 MB | 30.3 MB |

- 兩個採用的版本幾乎一樣；**壓縮版多 23 MB 工作集、15 MB private**（啟動時把 runtime 解壓到記憶體，跟 Mac／ShoWork42 的教訓相同），所以不壓縮。
- 繪製中（`WALL42_FORCE_DRAW`）跟停畫差不多（full 74.4／38.8 vs 76.8／39.0，檔名 wall42.exe）。
- **意外發現：檔名叫 `wall42.exe` 就多約 22 MB private**（同一個檔案改名成別的名字：73.1／38.1 → 52.6／15.6，重複量都一樣；
  跟放在哪個資料夾、有沒有 `--run` 無關）。模組清單相同。最可能是 Intel 顯示驅動依 exe 名稱存的 shader cache
  （`LocalLow\Intel\ShaderCache` 裡 wall42.exe 執行時改寫的那個檔 10.6 MB，W1 跑了幾百次截圖／各 preset 累積出來的）。
  所以 e2e 裡裝好的兩個版本都量到 73／38 MB，W1 的「75 MB 底線」在這台機器上也包含這份快取。沒去刪使用者的驅動快取驗證；使用者新裝的機器上應接近 51／16 MB。

## e2e（`tests\w2_install_e2e.ps1`）：50/50

兩個 exe 各跑（全部在沙盒 `WALL42_HOME`／`WALL42_DATA`／`WALL42_REG_ROOT`）：
`--version`；雙擊→出現 TaskDialog（#32770 'wall42'）→關掉後什麼都沒裝、沒東西在跑；`--install` 結束碼 0；bin 只有 wall42.exe 且與下載檔相同；
16 個 presets 與 repo 逐位元組相同；設定檔不存在→建立；Run（測試機碼）；「應用程式」項目各欄位；檔案版本資訊；
裝好的 wall42 從 bin 跑起來、`wall42.surface` 的父視窗是 WorkerW（Progman 底下）；log 在沙盒、讀沙盒設定檔；
同版本再雙擊→只顯示「已經安裝好了」、原本那個繼續跑；更新（把登錄的版本改成 0.0.1 再裝）→舊的停、新的從 bin 起來、畫面重新掛上、
使用者改過的設定檔與自己加的 preset 不動；從 bin 裡的 exe `--uninstall`→行程停、畫面從 WorkerW 消失、bin 被刪、Run 與清單項目拿掉、
log 刪掉、只留 presets 與設定檔。最後：本腳本開的 8 個 pid 全部結束；使用者真的 Run／Uninstall、`%APPDATA%\wall42`（本機不存在，仍不存在）、
`%LOCALAPPDATA%\wall42` 沒有多出 bin／presets；系統桌布設定（SPI 與登錄檔）不變；其他 19 個可見視窗位置／大小／最小化不變。

另外手動驗證 dev build `--install`／`--uninstall`（沙盒）：bin 是建置輸出的 15 個檔（不含 pdb 與子資料夾）、presets 從 repo 複製、解除安裝後全部清掉。

## 已知限制

- 沒有程式碼簽章：第一次執行 SmartScreen 可能警告。
- 更新時 presets 裡我們出的檔會被覆寫（使用者改過同名 preset 會被蓋掉；自己另存新名字的不動）。
- 雙擊的詢問視窗會拿到焦點（它是使用者主動開的程式）；e2e 只對自己開的行程的視窗送 WM_CLOSE。
