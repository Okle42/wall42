## 桌布層（實機，24H2）

`tools\Inspect` 在 wall42 執行中的輸出（摘要）：

```
Progman（頂層，ex=NOREDIRECTIONBITMAP|TOOLWINDOW）
  [0] SHELLDLL_DefView → SysListView32（圖示，全螢幕）
  [1] WorkerW（Progman 的子視窗，全螢幕）
        child wall42.surface  style=5C000000 ex=080000A0
wall42.surface parent=WorkerW grandparent=Progman
  WS_CHILD=True WS_DISABLED=True WS_EX_TRANSPARENT=True WS_EX_NOACTIVATE=True WS_EX_TOOLWINDOW=True
WindowFromPoint（三點）= 使用者最大化的終端機視窗（桌面被蓋住，正確）
  在 Progman 內的命中 = SHELLDLL_DefView → SysListView32（圖示在我們上面，點得到）
```

- 我們的視窗在 WorkerW 底下、WorkerW 在 SHELLDLL_DefView 底下 → 圖示之下、桌布之上。前景視窗從頭到尾沒變（沒搶焦點）。
- `PrintWindow(Progman, PW_RENDERFULLCONTENT)` 截到的是**圖示疊在粒子上面**的真實合成結果（flip-model swap chain 有被 DWM 合成進桌面層）。
- 結束後再截一次：沒有殘留畫面，回到使用者原本的桌布（純色 #4A5459，與登錄檔 `Colors\Background` 相符）。系統桌布設定從未被讀寫以外的方式碰過。
- 停畫 → 5 秒後縮 buffer → `debug-force` 信號恢復：立即 30 fps、截圖是全解析度的新畫面 → 關掉後再次停畫、再次縮 buffer。
- `.signal`：think（活動度升到 0.88、6 秒後自動到期）、insight、debug-suspend locked 開／關（走鎖定同一條路徑，SUSPENDED 時 0 幀）都實測通過；
  改設定檔 particleCount 420→300，下一秒 `♻ config reloaded`。

## CPU 與記憶體（kang preset，420 顆，30 fps）

量法：`tools\bench.ps1`，外部讀行程 CPU 時間差；全機％＝單核％÷8。停畫是使用者平常的狀態（視窗最大化蓋住桌面）。

| 情境 | CPU（單核） | CPU（全機 8 緒） | 工作集 | Private |
|---|---|---|---|---|
| 繪製中（WALL42_FORCE_DRAW，暖機 30 s、量 40 s） | 3.90% | **0.49%** | 81.5 MB | 40.1 MB |
| 對照：只 clear＋Present（FORCE_DRAW＋NO_DRAW） | 4.06% | 0.51% | 75.4 MB | 39.5 MB |
| **被視窗蓋住停畫**（暖機 60 s、量 60 s） | 0.26% | **0.033%** | 75.1 MB | 38.7 MB |
| Mac 參考：可見／遮擋 | 4.54%／0.07% | 0.45%／0.007% | 81 MB／47 MB | |

- 繪製成本跟「什麼都不畫」一樣——跟 Mac 的結論相同：成本在每幀醒來＋Present 的框架固定開銷，不在畫的內容。
- 停畫的 0.26%（單核）主要是每秒 tick（約 1.4 ms：熱重載 stat、信號檔、CPU 負載取樣、螢幕保護程式旗標、2 秒一次的覆蓋 fallback），
  其餘是少量 WinEvent。改善紀錄：第一版 2.3% → 範圍化 LOCATIONCHANGE hook 0.35% → 去掉 `Process` 查詢、覆蓋判定先做矩形篩選 0.26%。
- 記憶體：停畫比繪製少約 6 MB 工作集（swap chain 縮成 8×8）。Mac 停畫能降 42% 是因為 drawable 算在行程；
  Windows 的 swap chain 記憶體大多在顯示驅動／DWM 那邊，不算在我們的工作集，所以差距小。.NET runtime＋D3D 的底線約 75 MB。

## 設計決定

- **世界單位＝實體像素 ÷ 主螢幕 DPI 倍率**：preset 是以 Mac point 寫的，這樣大小／速度／連線距離看起來一樣；所有螢幕仍在同一個實體像素空間取聯合矩形，混合 DPI 也接得上。
- **Config 全欄位可省略＋逐欄容錯**：Mac 踩過「新增欄位非 Optional → 舊檔整份解碼失敗」；Windows 更進一步，型別錯也只丟那一欄。
- **時間與亂數注入 World**：單元測試與截圖可重現（截圖固定種子 42、固定 1/fps 步進）。
- **不用 WinForms**：主程式只要一個隱藏頂層視窗和子視窗，純 Win32 迴圈省記憶體與啟動時間（W2 的系統匣／面板再決定）。
- **沒有 input layout**：structured buffer＋SV_VertexID/SV_InstanceID，跟 Metal 的寫法一一對應，shader 可以逐行對照。
- **高解析度 waitable timer**：精準 30 fps 又不動全系統計時器解析度。
- **全螢幕 App**：由覆蓋計算涵蓋（一個視窗包住整台螢幕＝fullscreen），不另外呼叫 SHQueryUserNotificationState。
